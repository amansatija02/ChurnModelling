## 📌 Overview

Most churn projects stop at *"this customer will leave."* A bank can't act on that alone — it needs to know **the reason**, so it can decide what to do.

This project goes one step further. For every customer it:

1. **Predicts** the probability of leaving,
2. **Explains** which factors push that customer towards leaving (and which keep them loyal),
3. **Suggests** retention actions and shows the **what-if** risk if the bank acts,
4. **Compares** Deep Learning (ANN) against classic Machine Learning models.

Everything is delivered in an interactive Streamlit dashboard with Plotly charts.

```bash

python -m venv venv

# source venv/bin/activate     # macOS / Linux

# 2. Install dependencies

# 4. Launch the dashboard
streamlit run app.py
```

> ⚠️ The `models/` folder is generated by `train.py` and is not stored in Git. If the app shows
> *"Models not found"*, run step 3 first.

## 🧠 How the "Why" Works

The model gives a probability; the *reason* comes from a simple, model-agnostic check:

> For each feature, replace the customer's value with the value of a **typical loyal customer**
> (median / most common value among customers who stayed) and see how much the churn probability drops.

```
impact = P(churn | customer)  −  P(churn | customer with ONE feature set to "typical")
```

- **impact > 0** → this feature pushes the customer **towards leaving**
- **impact < 0** → this feature keeps the customer **loyal**

The same idea powers the **what-if**: set the *actionable* risk factors (activity status, number of products, credit card) to typical values and re-predict.

It works with the ANN and every ML model, so you can check whether different models agree on the same reasons.

## 📈 Results

Evaluated on a held-out **test set (20%)** the models never saw. The decision threshold is tuned on a separate validation set (best F1), because the default 0.5 performs poorly when only ~20% of customers churn.

| Model | Type | ROC-AUC | Accuracy | Precision | Recall | F1 |
|---|---|---|---|---|---|---|
| Neural Network (ANN) | Deep Learning | 0.851 | 0.843 | 0.618 | 0.597 | 0.608 |
| Logistic Regression | ML | 0.770 | 0.775 | 0.459 | 0.595 | 0.518 |
| Random Forest | ML | 0.853 | 0.835 | 0.588 | 0.624 | 0.605 |
| Gradient Boosting | ML | **0.865** | **0.852** | **0.652** | 0.585 | **0.617** |

*Numbers are from a reference run; neural-network training is slightly random, so expect small differences (about ±0.01) on your machine.*

**Takeaway:** the ANN performs on par with the best tree-based models. On tabular data like this, Gradient Boosting and Random Forest often match or beat neural networks.

> **Why not just use accuracy?** A model that predicts *"nobody leaves"* is already ~80% accurate. That is why precision, recall, F1 and ROC-AUC are reported.

## 🔎 Key Business Findings

From the 10,000-customer dataset (overall churn rate **20.4%**, about **186 M** in balances belonging to customers who left):

| Factor | Finding |
|---|---|
| **Number of products** | 2 products → **8%** churn, 1 product → **28%**, 3 products → **83%**, 4 products → **100%** |
| **Age** | Churn rises sharply from 41–50 (**34%**) to 51–60 (**56%**); under 30 only **8%** |
| **Country** | Germany **32%** vs France 16% and Spain 17% |
| **Activity** | Inactive members **27%** vs active members **14%** |

**What this suggests:** move 1-product customers to a second product, re-engage inactive members, investigate service quality in Germany, and review why customers with 3+ products leave.

## ⚙️ How It Works (Pipeline)

```
Churn_Modelling.csv
      │  load + validate (columns, duplicates, missing values)
      ▼
Stratified split: 60% train │ 20% validation │ 20% test
      │
      ├─► Preprocessing: scale numbers, one-hot encode Country & Gender
      │
      ├─► Train: ANN (Keras)  +  Logistic Regression / Random Forest / Gradient Boosting
      │
      ├─► Tune decision threshold on validation set (best F1)
      │
      └─► Evaluate on test set → metrics, ROC curve, confusion matrix, feature importance
                │
                ▼
          Streamlit app → prediction + reasons + insights + model comparison
```

**ANN architecture:** Input → Dense(64, ReLU) → Dropout(0.2) → Dense(32, ReLU) → Dropout(0.2) → Dense(1, Sigmoid), trained with Adam and early stopping.

**Input features (10):** CreditScore, Geography, Gender, Age, Tenure, Balance, NumOfProducts, HasCrCard, IsActiveMember, EstimatedSalary.

## ⚠️ Limitations & Notes

- **Correlation, not proof of cause.** The reasons show what the model associates with leaving, not guaranteed causes.
- **One feature at a time.** Reasons are tested individually, so combined effects (e.g. *older **and** inactive*) can add up to more than the churn probability.
- **Dataset.** `EstimatedSalary` appears to be random in this dataset (it has almost no relationship with anything else), so its impact is naturally near zero.
- **Fairness.** Gender is a model input and shows a difference in churn rates, but it is **never used for retention recommendations**. Review fairness before using any model like this for real decisions.
- **Learning project.** Built for learning and portfolio use, not production banking decisions.
